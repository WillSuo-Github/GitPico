## 对照和入口

继续使用原生 SwiftUI/macOS 桌面菜单、列表和表单；本轮只读取官方 [Organizing Repositories](https://www.git-tower.com/help/guides/manage-repositories/organize-repositories/mac)，没有激活本地 Tower 或 GitPico 窗口。文档确认了分组、排序、搜索与 `⌘⇧O` Quick Open 的入口。

- Welcome、文件菜单和工具栏 Repositories 菜单提供 `Repositories…` 与 `Quick Open…`。
- 仓库库左侧为全部、收藏、最近、未分组及嵌套分组；右侧显示名称、路径、所属分组和当前已打开标记。
- 新增本地仓库会先用 Git 验证工作目录。分组支持创建、改名、父分组迁移、按名称排序和移除。移除分组会把直属仓库/子分组移到原父级，保留内容。
- 仓库支持改显示名称、收藏、多选移动或移除、排序、移动到前一项及拖放插入。名称修改也用于最近菜单/Welcome 的显示。
- `Locate Repository…` 会先验证新位置的 Git 根目录，保持登记 ID、名称、收藏和分组；不会搬动文件或自动更换当前仓库会话。
- 移除登记只移除库与最近列表的条目，不删除工作目录。
- `⌘⇧O` 用于 Quick Open；原来同键的 Clone 改为 `⌘⌥O`，`⌘O` 仍是原生目录选择。

## 数据与保护

`RepositoryLibrary.swift` 保存统一版本化 JSON：登记 ID、规范路径、显示名称、收藏、分组及最近 ID。成功打开仓库时加入登记和最近列表；新增登记不冒充已经打开。最近列表保留 12 条，较早的登记仍留在库中。

旧 `recent-repositories.json` 仅作第一次迁移输入。新库不存在时规范路径、去重并保留顺序；新库已存在时不重复导入，因此移除的登记不会在正常重启后复活。旧文件不被删除。

保存先验证结构、组引用和循环，使用库旁的协作写入锁，再比较磁盘内容是否仍等于加载时的内容，最后原子替换 JSON。冲突、损坏或不支持的新版本会显示错误，保留磁盘原文及内存已有状态；Reload 后才继续编辑。库文件及其直接存储目录的符号链接被拒绝，系统路径中的合法上级链接不被当成库文件链接。上限为 5,000 个登记、500 个分组和 4 MB 元数据。

仓库成功打开后，即使库保存冲突，也保留已打开的仓库，并明确显示是库元数据保存失败。它不会把失败的旧库写回覆盖其他窗口。

拖放使用专用 Transferable 类型，载荷只含本次库会话 UUID 和登记 ID。多项整体验证后一次持久化；不同会话、已移除条目和无效目标拒绝，重新加载使旧令牌失效。

## Quick Open

搜索覆盖名称、路径和分组完整路径，以空白分词、大小写/重音折叠匹配。名称精确/前缀结果优先，再参考收藏和最近打开顺序。列表最多显示 100 条，避免把整个大库一次绘制出来。

文本框默认获得焦点，箭头调整选中项，Return 或双击打开，Escape 取消。选项在搜索结果变化后重新校验；打开前再次校验 ID 与保存路径，防止旧菜单或旧结果打开后来重新定位的另一个目录。所有打开沿用当前仓库窗口与 busy 保护，没有新增多窗口/标签页行为。

## 顺手修复的真实路径问题

Git 的 `rev-parse --show-toplevel` 会在路径后增加一个换行。旧代码裁掉所有末尾换行，导致真实目录名以换行结尾时可能退化成相邻的另一个仓库路径。

先以两个不同临时工作目录复现输出，再将 `GitRepository.open` 改为严格 UTF-8 读取并只移除一个 Git 输出结束换行。回归用例让两目录分别处于 main 和 requested 分支，确认打开的是请求目录而不是旁边的仓库；没有写任何个人目录。
