# Validation — GitPico 0.3 — 2026-10-23

## Scope and reference

Implemented line staging/unstaging, side-by-side text diffs, and an integrated conflict-resolution workflow in Swift/SwiftUI with a macOS 26.0 deployment target.

The installed Tower 18 was inspected through native accessibility and screenshots against the same isolated repositories generated by `script/create_review_demo.py`. No production repository was modified. Tower's conflict page shows the operation card above the file list and current/incoming version cards; GitPico adopts that placement and adds an inline result editor. The conflict editor is a functional extension, not a claim of identical Tower layout.

References: [Tower line diff](evidence/tower-line-reference.png), [Tower conflict page](evidence/tower-conflict-reference.png).

## Automated verification

`swift test`: **36 Swift Testing tests passed, zero failures**. Parameterized cases include four selected-line combinations and all three integration types. The final suite finished in 28.211 seconds. [Full log](evidence/swift-test-v3.log).

New coverage includes:

- Stage only an addition, only a deletion, or a selected replacement; verify exact index bytes and unchanged working-file contents.
- Unstage one selected line while retaining other staged changes; reject stale index and working-file previews.
- Apply selections across separated chunks with different offsets; return the index to its original contents.
- Partially stage new/deleted files, quoted Unicode paths and files without a final newline; preserve CRLF bytes and refuse structural mode changes.
- Align additions/deletions into paired split-view rows without losing lines.
- Parse standard/diff3 conflict blocks, preserve CRLF, choose either/both/base and retain unresolved blocks.
- Resolve, stage and continue merge/rebase/cherry-pick conflicts, verifying exact index contents.
- Refuse unresolved markers, externally changed files/index entries and symbolic-link writes.
- Accept a deletion in modify/delete conflicts; accept exact bytes for binary regular files; preserve executable mode for edited resolutions.

## Repairs made during verification

- Standard Swift Character splitting did not split CRLF grapheme clusters in diff bodies. Switched to Foundation newline component splitting; exact-byte CRLF line staging now passes.
- Conflict separators ending in CRLF were not recognized by the initial marker predicate. Recognize whitespace suffixes and preserve original terminators.
- Line selections could outlive an asynchronous diff reload. Tie selection state to the path, side and rendered diff so obsolete selections disappear.
- Full text labels in the compact diff-layout picker overlapped adjacent controls. Use accessible icon segments; constrain the two split panes to equal widths.
- Preserve conflict drafts with their original snapshots across navigation; stale-save guards still apply after returning to the file.
- Strip merge-template comments on Continue. The integration regression test now verifies completed merge/rebase/cherry-pick messages contain no `# Conflicts:` section. The earlier History screenshot predates that cleanup fix.

Preserved pre-fix CRLF regression evidence: [edge-failure-v3.log](evidence/edge-failure-v3.log). The final suite above includes the repaired case.

## Limits

- This is a functioning text workflow, not complete Tower parity. Toolbar grouping, font/row density, graph ordering and additional workflows still differ.
- Partial staging intentionally refuses renames/mode changes, conflicts, ignored-whitespace previews and truncated chunks. Use whole-file actions for unsupported structural changes.
- Conflict editing is limited to UTF-8 regular files up to 1 MB. Whole-version selection supports regular files up to 16 MB. Symlinks/submodules require an external tool. Drafts are session-local; quitting loses unsaved draft edits.
- A failed Git add/filter after a saved resolution leaves the result on disk; the error is shown and the conflict is not claimed resolved.
- Runtime host is macOS 27.0.1. Manifest, bundle and Mach-O minimum are 26.0; macOS 26 runtime execution remains unverified.
- Hosted authentication, production signing, large-repository performance, comprehensive light appearance and VoiceOver audits remain outside this verification.
- Source is uncommitted and unpushed.
