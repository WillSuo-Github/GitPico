## Health and practical priorities

**Overall parity: incomplete.** Existing local text workflows are usable within documented boundaries. Branch/tag/remote administration and the core stash workflows now have disposable-repository evidence. Discard recovery and patch transfer now have guarded regular-file workflows; hosting/account workflows, broader Undo and repository extensions still have substantial gaps. The disabled Pull Requests row is not a working feature. Setting Git signing configuration is not equivalent to key management or signature verification. Branches Review's ancestry check is not PR-aware merge detection. The history Undo journal is not Tower's broad Undo.

**0.5 implementation batch:** file lineage and revision-specific diff/raw/blame; immutable arbitrary-revision and merge-base comparisons; single-commit Revert including explicit merge parent and conflict continuation/abort/Undo/Redo. These are marked partial where Tower provides additional scope or UX.

**0.6 implementation batch:** branch rename/delete/tracking/archive/pin, tag lifecycle, remote URL/configuration management and recovery, reviewed publication/force-with-lease, stash index/pop/file/chunk/snapshot/rename/delete/recovery. Signing remains partial; see the row boundaries below.

**Current interaction batch:** automatic stash offers with optional reapplication and persistent recovery; selected-line stash application; reviewed drag routes for stashes/refs/commits. The user requested background-only testing during native acceptance. Further foreground tests stopped immediately; the matrix distinguishes successful native file/selected-line drops from routes tested only through headless routing/core tests. Marketing version is now fixed at 0.01, with date-based Build Numbers; earlier version labels remain historical.

**Background drag follow-up:** actual AppKit destination callbacks now have windowless coverage, including all pasteboard items, cancellation/busy-state revalidation and captured HEAD/plan guards. The 100-test complete run passed. This does not establish real mouse/SwiftUI List/layout acceptance.

**Local changes batch:** reviewed file/chunk/line discard, persistent restart-safe recovery and patch import/export. Patch targets include worktree, index and both; native save/open panels and commit export menus are connected. Background-only evidence and conversion/link/size boundaries are documented in [local changes validation](VALIDATION-LOCAL-CHANGES-2026-10-24.md). Historic file/ZIP export and a unified non-history Undo remain open.

**Historical files batch:** immutable historical snapshots, regular-file restore with persistent backup, original files/new-folder export and ZIP for selected files/folders or entire commit/branch/tag trees. Context menus follow the earlier local Tower capture; no new foreground UI inspection was performed. See [historical files validation](VALIDATION-HISTORICAL-FILES-2026-10-24.md). Merge-commit patch variants and all-reference file lineage remain open.

**Repository navigation batch:** persistent repository registrations/favorites, nested groups, custom names, scoped search, ordering and relocation; Cmd-Shift-O Quick Open with keyboard selection. Existing recent paths migrate once into the unified library. Native panels/drag/keyboard visual acceptance remains pending under background-only testing. See [repository library validation](VALIDATION-REPOSITORY-LIBRARY-2026-10-24.md).

**Browsing and tools batch:** all/ignored/assume-unchanged working files, recoverable force-add, Cmd-Shift-A Quick Actions and configurable external diff/merge sessions. Tool comparisons use copies; merge results need explicit review and stale-source/result checks before staging. Backend and headless helper coverage passed; no real GUI was launched. See [browsing/tools validation](VALIDATION-BROWSE-TOOLS-2026-10-24.md).

**Worktree/submodule batch:** related-repository source-list entries, searchable compact list/detail browsers, branch-context Worktree checkout, reviewed operations and Quick Actions. Worktrees support new/existing/detached creation, open, lock, move, verified repair and guarded removal. Submodules support add/init/recursive clone, Fetch/recorded-version update/revision checkout/open, URL/path/sync/repair/deinitialize/remove, retaining Git history. See [validation and remaining boundaries](VALIDATION-WORKTREES-SUBMODULES-2026-10-24.md). No foreground inspection was performed.

**Advanced related repositories:** nested Worktree/submodule migrations reconnect Git files and core.worktree at every initialized level, including embedded and per-linked-worktree storage. Reviewed multiselect batches persist progress and stop at failures; management backups support guarded directory/index/config restoration, resume after interruptions during restoration, new-folder extraction, and isolated recovery of older index-only metadata. See [advanced validation](VALIDATION-RELATED-ADVANCED-2026-10-24.md). Arbitrary native-operation crash results are not assumed safe to overwrite.

**Implementation order:** remaining P1 local data operations (broader Undo and remaining export variants), advanced Worktree/submodule cases and external-tool GUI acceptance; account adapters/PRs with test providers; P2 automation and workflows; P2/P3 appearance/integration. This is an ordering decision, not an exclusion of lower-priority missing features. Every write flow needs concrete disposable-repository acceptance, not only command wrappers.

**Preview performance follow-up:** per-session bounded history/presentation caching, tip revalidation, cancellation and asynchronous graph/sidebar preparation now avoid navigation-wide scans. Compact native toolbar groups and search follow saved local Tower captures. See [preview validation](VALIDATION-PREVIEW-PERFORMANCE-2026-10-24.md); this does not establish live mouse/rendering parity.

**Navigation/menu follow-up:** distinct Repository/Branch/Commit menus, contextual enablement, a branch preview menu and explicit Check Out, history query/options/selection restoration, and windowless light/dark row captures. See [experience validation](VALIDATION-EXPERIENCE-2026-10-24.md). Exact live Tower layout and native keyboard/mouse acceptance remain pending.

**Working copy follow-up (2026-10-25):** prepared file-list/diff presentation, stable multi-selection, explicit selected-file staging, partial-stage checkbox behavior, inline diff Retry and commit readiness/draft/success handling. Disposable-repository index/HEAD/worktree checks and light/dark row captures are documented in [working copy validation](VALIDATION-WORKING-EXPERIENCE-2026-10-25.md). No new foreground acceptance.

**Incremental refresh follow-up (2026-10-25):** index writes retain working/history state and commit refreshes bounded affected data without full repository scans; related management data reloads on demand with stale-session/epoch guards. Same-fixture before/after timing and disposable-index/HEAD checks are in [incremental refresh validation](VALIDATION-INCREMENTAL-REFRESH-2026-10-25.md). Checkout/Stash/integration incremental refresh, automatic recovery and conflict redirection are covered by the [working-tree refresh follow-up](VALIDATION-WORKING-TREE-REFRESH-2026-10-25.md). Full Tower rendering parity remains unverified.

**UX/AX review limits:** screenshots confirm only the pictured dark-mode routes. Tower's Blame places code on the left and attribution on the right; 0.5 follows that arrangement. GitPico still differs in toolbar grouping, graph rows, selection colors, text highlighting, menu richness and action discoverability. Native AX trees were inspected; complete VoiceOver, focus order, light mode and macOS 26 runtime acceptance remain unverified. No invented numeric UX score is assigned.
