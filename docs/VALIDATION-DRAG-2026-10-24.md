## 本轮修正

### 原生放置生命周期

将原生接收器拆为可独立测试的 `NativePicoDropView`。SwiftUI 的桥接和测试使用同一套 Enter、Update、Prepare、Perform、Exit、End、Conclude 实现。

之前的 `draggingUpdated` 会沿用最初的接收结果。现在悬停更新和落下前都会重新读取完整数据、检查仓库会话、忙碌状态及来源允许的复制／移动操作。数据中途改变、来源操作不支持、仓库切换或操作变忙时，都会取消接收并清除高亮。

Perform 会先消耗当前接收会话，再派发确认请求，避免重复回调打开第二个确认表单。退出、取消和结束拖动也会清除状态，普通点击继续传给下方 SwiftUI 控件。复制和仅允许移动的来源都已覆盖。

### 多项文件

旧读取方式只取拖放板上某个类型的第一份数据，可能漏掉后续项目。现在会读取每一项，检查全部会话令牌；多个工作区文件合并为一个排序、去重后的选择。文件与引用等混合数据会整组拒绝，不会只保存第一项。

每个内部令牌最多 512 字节，一次最多接收 512 个令牌项目；常规多文件选择也可由一个令牌携带。真实文件内容和预览留在进程内存中，不写入拖放板。测试使用独立命名的拖放板，结束后释放，不改用户的通用剪贴板。

### 目标分支与 HEAD

分支或提交拖到 HEAD 时，会把目标分支名和提交哈希一起固定到 `IntegrationRequest`。后续确认保留原始目标，不允许另一个调用方传入“更新后的 HEAD”来覆盖检查。

隔离仓库测试实际执行了：拖到 main、外部切换到另一个分支、提交之前的确认请求。操作会报 HEAD 已改变，另一个分支、提交和工作区保持不变。集成表单也会等 HEAD／提交预览加载成功后再允许确认。

提交拖放准备 Rebase 计划时也核对原始目标。新增用例专门覆盖“哈希相同、分支不同”：外部切换后，异步计划生成会被拒绝，不会为错误分支打开可执行的计划。

### Rebase 排序

历史列表按新到旧显示：行顶边表示回放顺序更晚，底边表示更早，中间准备 Squash，按 Option 则准备 Fixup。无窗口原生回调测试核对了四种计划结果，准备阶段不改写 HEAD。

计划列表按旧到新显示。共享的 `RebaseStepEditing` 负责插入目标行之前或之后，向两个方向拖动的结果一致。移除了旧的 List 移动处理器，避免两套排序入口并存；箭头按钮继续保留。

计划内的拖动令牌新增计划 UUID。重新加载计划后，旧令牌立即失效，即使同一个提交仍在新计划中也不能复用。仓库会话和忙碌状态检查继续生效。

## 无窗口验收范围

`NativeDropTests.swift` 使用 `NSDraggingInfo` 协议替身和真实独立拖放板，在没有窗口的 NSView 上调用实际接收回调。这一轮新增八项应用测试，覆盖：

1. 整份 Stash、仅允许移动的来源、准确派发确认、重复 Perform 不重复请求；确认前 Git 不变。
2. 悬停期间操作变忙、数据被替换、不支持的来源操作权限。
3. 多项文件完整合并、去重、混合数据拒绝；确认前文件和 Stash 不变。
4. 无效／过大数据、错误仓库会话、退出／取消清理和点击透传。
5. 原生放置、确认请求、真实 Git 串联的外部分支切换保护。
6. 历史行两侧重排、Squash、Fixup 的四种落点；只准备计划，不修改 HEAD。
7. 重新加载计划或仓库后，旧拖动令牌失效。
8. Rebase 计划生成前发生相同哈希的分支切换时，仍拒绝错误目标。

新增 GitCore 测试验证计划行向前／向后移动、插入之前／之后，以及自拖或不存在的来源不改变计划。此前的自动 Stash、逐行应用、冲突恢复、远程管理与历史操作测试也在最终完整运行中通过。
